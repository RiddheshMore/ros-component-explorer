System Architecture & Query Flow

High-Level System Architecture

The system is composed of three distinct layers that work in concert to deliver a seamless search experience.

Frontend

A user-friendly web interface built with Gradio for query input and result display.

➜

LLM Service

Acts as an intelligent translator, converting natural language into structured Solr queries.

➜

Backend

The data powerhouse, using Apache Solr to index component data and execute complex searches.

User Query Flow

Follow a query's journey from your keyboard to the final results on your screen.

1.
Query Input: User enters a plain English query into the Gradio frontend.
2.
LLM Translation: The query is sent to the LLM Service, which translates it into a structured Solr query.
3.
Backend Search: The Solr query is executed by the Backend against its indexed component data.
4.
Results Display: The matching components are returned to the frontend and displayed to the user.

Sentence Transformer Usage Overview

1. Model Setup & Initialization

The all-MiniLM-L6-v2 model is used to generate 384-dimensional embeddings, with CUDA support for acceleration.

# In VectorGenerator class
from sentence_transformers import SentenceTransformer

def __init__(self, model_name: str = "all-MiniLM-L6-v2"):
  self.model = SentenceTransformer(model_name)

2. Component Text Processing

Rich text descriptions are created by combining component name, type, description, package, and ROS topics.

3. Embedding Generation

Component descriptions are converted into 384D vectors in batches for efficiency and stored with the component data.

4. Query Processing

User queries are also converted into a 384D vector to find components with the closest conceptual meaning.

5. Current Status & Limitations

  • Working: Model initialization, text processing, embedding generation, and query vectorization.
  • Limitations: Vector storage is not fully configured in the Solr schema, causing the system to fall back to text search instead of true vector similarity search.

🤖 AI Response Generation Pipeline

1. Response Generation Flow

A 5-step process: parse query, translate to search params, execute search, rank results, and synthesize a human-readable response.

2. Response Type Detection

The AI automatically determines the response style (recommendation, comparison,list) based on query keywords.

3. Key AI Response Characteristics

  • Natural Language Understanding: Parses user intent from queries.
  • Context-Aware: Provides different response styles based on query type.
  • Reasoning: Explains why recommendations are made.
  • No External LLM APIs: Uses rule-based NLP and Sentence Transformers for semantic understanding.

4. Smart Response Features

  • Intelligent text truncation for readability.
  • Contextual reasoning based on detected requirements (e.g., sensors, environment).
  • Graceful handling of missing data and "no results" scenarios.
  • Rich Markdown formatting for better readability.
